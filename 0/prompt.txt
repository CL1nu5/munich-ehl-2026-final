## 2. Buyer message schema

Source: `api.md:188-203`.

- **`subject`:** ≤ 300 characters.
- **`body`:** plain text, ≤ 8,000 characters.
- **`term_sheets`:** 0–3 items of `{"terms": {...every negotiable field}}`.
- **`refs`:** data IDs, ≤ 20. The field is called `refs`, not `cited_ids`. IDs written in the body count too.
- **`attachments`:** ≤ 5 items of `{name, type: md|csv|json|pdf|xlsx, content_b64}`. Only md, csv and json are read.
- **`action`:** one of
  - `null`
  - `{"type":"accept","term_sheet_id":"offer:…"}` – takes that supplier's standing term sheet
  - `{"type":"walk_away"}` – ends the whole case with no deal
- **Errors:** `422` for an invalid message (no round is used). `409` for a thread that has ended, the round limit, or a late message (`api.md:101-105`).
- **Structured alternative:** `POST …/moves` with typed `claims` (`api.md:180-186`).

Claim checking (`api.md:233-271`):
- At most 3 claims are checked per message, one argument per sentence.
- Tolerance is ±0.5 percentage points for %, otherwise ±0.5 %.
- `contradicted` costs trust.
- Citing a rival's quote reveals it to the supplier you cite it to.

Term fields (`api.md:285-303`):
- `unit_price` (2 decimals), `payment_days` (0–120), `lead_time_days`, `volume_per_year`
- `contract_months` (0–36; 0 = a single order, which counts as one year's lot)
- `effective_date` (ISO date)
- `index_clause` (null or `{series, material_share, deadband_pct, base_month}`)
- `incoterm` (EXW/FCA/DAP), `tooling_eur`, `ppm_commitment`, `chargeback_eur_per_complaint`

`complete_offer(case, terms)` (`cost.py:199-211`):
- Returns exactly the negotiable fields.
- Gaps are filled from the buyer's plan: need, horizon×12 months, reference payment days, the needed lead time, and the cheapest Incoterm.
- Otherwise it falls back to `term_options[0]`.
- Each value is snapped to the nearest allowed option (`snap`, `cost.py:189-196`), and price is rounded to 2 decimals.

## 4. Cost, score and end-of-case feedback

**C** is computed in `cost_breakdown()` (`cost.py:125-159`) and summed by `total_cost()` (`cost.py:162-167`, `inf` if there is no price). The formula is at `api.md:379-401`. Components:
- price
- uncovered_need, fallback_risk
- payment_terms (`spend·r·(d_ref − payment_days)/360`)
- freight, late_delivery, quality, tooling
- index_clause, index_risk
- relationship – only for stabilise / secure_supply, and only if you pass a `supplier` estimate (`supplier_value`, `cost.py:71-100`; `soft()`, `cost.py:103-108`)

`closing_terms()` (`cost.py:27-44`) layers the inputs in this order: buyer plan, then supplier standard terms, then fixed terms, then the term sheet. Unknown Incoterms are treated as the costliest.

**Score** (`cost.py:170-175`, `api.md:420-426`):
```
score = clip((C_open − C_deal)/(C_open − C_best), 0, 1)
```
- `C_open` is the cheapest opening quote that keeps the must-haves.
- `C_best` is the cheaper of the alternative and the best package any supplier would ever accept. It is hidden and fixed per case.
- With no deal, the score is computed from `c_alt` (0 if there is no alternative). A broken must-have scores 0.

**What the agent sees at the end:**
- **Closing reply:** the accept or walk-away reply carries a `result` without the trace (`api.md:364-375`; sim `_public`, `sim.py:363,454`). Fields:
  - `ended`, `deal`, `must_haves_ok`, `supplier_id`, `offer_id`, `terms` (with standard terms filled in)
  - `c_open`, `c_deal`, `c_alt`, `c_best`, `score`
  - `cost_breakdown` (per component, relationship charge included)
  - The numbers are exact in every set.
- **`GET /v1/sessions/{sid}` after the end:** adds `result.trace`, a list of `{round, actor, move, reasons}` where `reasons` is the supplier's reasoning in words. It also adds `replay_url` (`api.md:119-124,375`; `sim.py:420-421`). In the final, the trace only comes after the final.
- **`example_inputs/.../4_session_state.json`:** this capture is mid-case (`status: open`, no `result`), so it does not show the end-of-case shape.

**Feedback endpoints a learning loop can use after a case:**
- `GET /replay/{sid}` (`api.md:175-178`): every e-mail and the supplier's reasons for each move. It is not under `/v1`, and `client.py` has no method for it.
- `GET /v1/sessions/{sid}/backoffice` (`api.md:126-130`): the supplier's internal role chatter, only after the end. `client.backoffice()` exists (`client.py:113`). The kit's harness blocks it (`harness/transport.py:51`), so call it directly.

So a learning loop can consume `result.cost_breakdown`, `c_best`, `trace[].reasons` and the backoffice. The CLI prints only the summary and the replay link (`cli.py:44-46,126-128`).

## 5. Starter LLM agent (`agents/llm.py`)

- **`SYSTEM` prompt** (`llm.py:29-51`):
  - The model returns JSON: `{"supplier_id", "action": "send"|"accept"|"walk_away", "subject", "body", "term_sheets":[{...}]}`.
  - Rules: cite ID plus figure, ≤ 120 words, don't leak urgency, don't take the first offer.
- **`prepare()`** (`llm.py:106-118`), once per case: the case JSON, the trigger letter (`package.document`, first 2,500 characters) and the facts for suppliers, parts and refs (`fact()` reads `case.facts`, then `package.lookup`).
- **`render()`** (`llm.py:123-144`), per turn:
  - The brief.
  - The alternative's C.
  - Per live thread: status, `moves_left`, the standing sheet with its C (using `standard_terms` from the quote PDF) and the standard terms.
  - The last 6 messages (head fields plus 800 characters of body) and attachment text (1,500 characters).
  - The relationship cost is not included.
- **Attachments:** `play.fetch_documents` (`play.py:118-123`) downloads every attachment and stores its text in `att["text"]` via `docs.read_document` (PDF through pypdf, XLSX rows with formulas, `docs.py:28-43`).
- **`guard()`** (`llm.py:146-193`):
  - Accept only if must-haves hold and the sheet beats the alternative.
  - Merge each proposed sheet onto the standing terms, then `complete_offer`, then dedupe.
  - Strip unknown data IDs (`ID_RE`, `llm.py:27`).
  - Clip body and subject.
- **Fallback:** `NaiveAgent` (anchor −10 %, split the difference, accept on agreed/final_offer, `naive.py`).
- **`llm_from_env()`:** Anthropic or OpenAI-compatible, 45 s timeout.

## 6. What the scripted supplier in `sim.py` does

Constants (`sim.py:33`): `OPEN_UP = 0.10`, `STEP = 0.02`, `FLOOR = 0.90`, `FINAL_ROUND = 5`.

- **Opening** (`sim.py:219`): `current (or fallback) × (1.10 + 0.02·i)` for supplier index i. Only `unit_price` is stated.
- **Standard terms** (`sim.py:220`): the first `term_options` value for each field, so payment is 14 days. This code also assumes `unit_price` is the first negotiable field.
- **Each message** (`sim.py:157-170`):
  1. It computes its next price as `max(opening·0.9, stated − opening·0.02)`.
  2. If none of your sheets has a price (or you sent none): "We keep our offer". The round still counts (`sim.py:371`).
  3. If your highest-priced sheet is at or above that next price: `agreed`, and it adopts your whole sheet. Non-price terms are ignored entirely, so 90 payment days or DAP come free.
  4. If its status was already `final_offer`: `walked_away`.
  5. If the round is ≥ 5: `final_offer`.
  6. Otherwise: `open` with a counter at the new price.
- **Claims** (`sim.py:149-156`): it checks only that each ID exists (first 3 IDs). Unknown IDs come back `contradicted`, repeats `duplicate`; figures are never checked.
- **Cost breakdown:** the word "breakdown" in the body triggers an XLSX with fixed 50/30/15/5 % shares (`sim.py:69-83,157`).
- **Constant behaviour:** signals are always `{1, 30}`, there are no roles (always `sales@`), the same `reasons` string every time, and no tone, data or relationship effects.
- **C_best** (`sim.py:285-300`): floor price × every combination of options. **Walk-away** ends the whole session (`sim.py:341`).
- **What it teaches:** API mechanics, the 60-second clock, timeouts, 409/422 errors, `X-Move-Id`, documents, the result shape and multi-thread RFQs.
- **What it cannot teach:** real concession curves, trading on non-price terms, claim figure checking, persuasion, final-offer risk or supplier personalities.

## 2. `facts.json` ID format and how to check a fact before citing it

- `data/facts.json` is a flat dict with 10,356 keys. By type: po 5400, idx 2258, qn 1033, fc 495, sc 414, ctr 326 (46 contracts + 280 clauses `ctr:&lt;no&gt;#&lt;clause&gt;`), doc 208, quote 108, rfq 47, news 39, cost 28.

- The fields the arena checks, per type:
  - `po`: unit_price, change_pct, qty, price_unit, date
  - `sc`: otd_pct, otd_confirmed_pct, ppm, colour
  - `idx`: value, month
  - `cost`: unit_cost, confidence_pct
  - `quote`: unit_price, payment_days, lead_time_days, incoterm
  - `doc`: asked_pct, asked_price, days, effective_date
  - `ctr`: days, series, material_share, type
  - `fc`: change_pct, volume_per_year
  - `news`: supplier, topic
- Example: `"sc:70110@2026Q3": {"colour":"amber","otd_pct":85.2,"ppm":712,...}`, and `"doc:20260911-70110-P01": {"asked_pct":9.5,"asked_price":138.55,"days":51,...}`.
- **Check rules** (`brief/api.md:245-257`):
  - Two `idx` of the same series, at most 12 months apart, ending within the last 12 months: the % change is checked.
  - `sc` rows: the mean otd or mean ppm is checked.
  - 2-8 `po` of the same part: the order prices are checked.
  - A `doc` letter plus a `ctr`: notice days are checked.
  - Tolerance is ±0.5 percentage points for %, otherwise ±0.5 %.
  - An unknown ID or a wrong figure counts as `contradicted`. A true fact about another supplier, or an index window that's too old, counts as `irrelevant`.
  - At most 3 claims per message, and each ID counts once per case.
- **How to check before citing:**
  1. `pkg.facts.get(id)` must not be `None`. `pkg.lookup()` also falls back to table rows (`starter-kit/arena_kit/data.py:76-78`), so a hit there doesn't prove the ID is citable.
  2. Recompute your figure from `facts[id]` fields using the formula above.
  3. Assert it is within tolerance.
  4. Check that `facts[id]["supplier"]` equals the case supplier and `part` equals the case part.
  5. Keep a per-case set of IDs already cited, to avoid `duplicate`.

## 4. Data-quality traps (`data/KNOWN_ISSUES.md`)

- **Lines 5-6, 10:** OTD differs by 10-30 points depending on the date used (requested, confirmed or posting). Cite the `sc` rows, not your own calculation. PPM on single lots is jumpy.
- **Line 9:** prices are per `price_unit` of 1, 100 or 1,000. Line value = qty × price / price_unit. Negotiate in the same unit.
- **Line 11:** `sup:71999` is the old record of `sup:70210`. Only `spend_cube` has a row under 71999; the news item `news:20240514-00` records the rename.
- **Line 12:** `stale_condition` PO lines (83) show a price variance, not the real price.
- **Line 16:** index series end at different months. LCI-C ends 2026-06, PPI-* at 2026-08, AS/CU/ECB/WB/SMARD at 2026-09. The index window must end within the last 12 months of the data.
- **Line 15:** quotes leave out fields such as validity_days, incoterm and payment_days.
- **Line 18:** small suppliers give turnover only as a band.
- **Line 19 and `company.md:25-30`:** should-cost has a 5-15 % error. Rows that model the supplier's own plant (with a supplier_id) are about ±5 %. For other countries scale by about 0.7-1.1.
- **Line 14:** some suppliers are paid late. This matches the "Overdue invoices" `-P` emails and lowers their goodwill.
- **Other:** `-N` documents and `news.topic='noise'` are distractors (`brief/brief.md`: "Some notes are just noise").

## 1. Agent lifecycle

**Loading**
- `load_agent` (`arena_kit/harness/worker.py:15-21`) runs `importlib.util.spec_from_file_location("team_agent", agent_path(name))` and returns `module.Agent()`, called with no arguments.
- `agent_path` (`arena_kit/harness/config.py:37-43`) requires the file `agents/{name}.py` and an identifier-style name.
- The module is loaded as `team_agent`, not as part of a package, so relative imports fail.
- The worker's `sys.path[0]` is `starter-kit/` (it runs with `-m` and `cwd=ROOT`), so `from agents._helpers import X` works.
- `agents list` shows every `agents/*.py` except files starting with `_` (`cli.py:267`). Prefix helper files with `_` or put them in a subfolder.

**Process model**
- `Engine.play_case` creates a new `AgentProcess(self.cfg, self.models)` for each case (`engine.py:166`).
- The subprocess `python -m arena_kit.harness.worker` starts the first time it is called (`agent_process.py:37-38`), which is the `prepare` call.
- The same process and `Agent` instance serve `prepare` and every `decide` of that case. It is killed in the `finally` block (`engine.py:349`).
- **Nothing is reused across cases.** Each case has its own process.
- Up to `parallel` cases run at once (`engine.py:36,156`; default 10, `config.py:59`). Several agent processes can therefore write to your memory files at the same time. Use file locks (`fcntl`) and atomic renames.
- After any exception or timeout, `AgentProcess.call` kills the process (`agent_process.py:56-60`). A later call would start a new process with a new `Agent()` and no `prepare`.
- After a crash, the engine restarts. `prepare` is skipped if it already ran (`engine.py:170`), and `state` is restored from the journal's `agent_state` (`engine.py:169,282`). A new `Agent()` instance never sees `prepare`, so keep durable per-case data in the returned JSON `state`.
- `agents check` is different: it uses one worker for S01, S02 and S03 in turn (`cli.py:226-252`).

**`prepare(context)`**
- `context = {"case": case, "parameters": cfg["parameters"]}` (`engine.py:175`). Nothing else is passed.
- It receives no `services`, so it cannot call the LLM (`worker.py:52`).
- Its timeout is `decision_seconds` (`engine.py:174`). Time spent importing your module counts against it.
- It returns the initial `state`, which must be serialisable JSON with no NaN (`state.py:13-14`, checked at `worker.py:56`).
- If it fails, the case is recorded as "Agent preparation failed" and no session is opened (`engine.py:178-183`).
- In the final, `case` also contains `wave`, `open`, `seconds_left` and `theme`.

**End-of-case hook: none**
- `worker.py:51-54` sends every method that is not `prepare` to `agent.decide`. Adding a `finish` method therefore needs a change to the worker as well.
- The agent cannot reliably notice the end of a case:
  - It knows when it returns `accept` or `walk_away` itself, but never sees the result.
  - Cases closed by the engine (timeout, wave cap, invalid output) or by suppliers walking away happen without any `decide` call.

**Where the final result becomes known in `engine.py`**
- `record_result` (`engine.py:351-358`) stores `result`, `end_reason` and `rounds` from `GET sessions/{sid}`. It is called at lines 208, 254, 296, 319, 326 and 337.
- Line 232 stores `result=reply.get("result", reply)` from a supplier reply that ended the case, without `end_reason` or `rounds`.
- Line 318 stores the result returned when the agent closes the case.
- Error exits without a result: lines 182, 189, 306 and 338-343.

**Cleanest place for a post-case hook:** the `finally` block of `play_case`, before `await agent.close()` (`engine.py:344-349`). Every exit path passes through it. Sketch:
```python
stored = self.journal.cases().get(cid, {})
if stored.get("result") and not self.stop.is_set():
    try:
        await agent.call("finish", self.cfg["decision_seconds"],
                         outcome={"case": case, "result": stored["result"],
                                  "end_reason": stored.get("end_reason")}, state=state)
    except Exception:
        self.journal.event("fallback", case=cid, phase="finish")
```
Add a branch to `worker.py` that calls `agent.finish(outcome, state, services)` if it exists.

Points to handle:
- `state` and `threads` may not exist yet if the exception happened early. Use `locals()` checks or set defaults.
- The hook still holds the case's `slots` semaphore, so it delays the next case.
- It uses the model call budget.
- Changing `arena_kit/` changes `code_hash`, so runs started before the change cannot be resumed.

**Alternatives that leave the harness unchanged**
- Run a separate "learn" step after the run that reads `.runs/RUN_ID/run.sqlite` (see section 5).
- Or, in `prepare`, scan `../.runs/*/run.sqlite` read-only for finished cases that are not yet in memory, and record them as text. `prepare` has no LLM access, so any LLM reflection would have to happen in `decide`, inside its budget.

## 2. Observation and services

**Observation** (`engine.py:266-272`):
```python
{"case": case,
 "threads": deepcopy(threads),            # {supplier_id: [msg, ...]} oldest first, both directions
 "ready_suppliers": ready,                # live suppliers with no request in flight
 "seconds_left": {s: deadline-now for s in ready},
 "wave_seconds_left": None or cap-now}    # None outside the final
```
- Buyer messages are stored as `{**sent_message, "from": "buyer"}` (`engine.py:219`).
- Supplier messages have these keys (`sim.py:122-137`, `brief/api.md:189-203`):
  - `thread_id`, `message_id`, `in_reply_to`, `from` (e.g. `"sales@70270"`), `subject`, `body`, `refs`, `action`
  - `term_sheets`: `[{"term_sheet_id": "offer:..", "terms": {...}}]`
  - `status`: `open`, `final_offer`, `agreed`, `walked_away` or `no_bid`
  - `signals`: `{"reply_delay_days", "validity_days"}`
  - `claim_results`: `[{"index", "result": "verified"/"irrelevant"/"contradicted"/"duplicate"}]`
  - `missing_fields`
  - `attachments`: `[{"attachment_id", "name", "type", "text" or "error"}]`
- Attachment text is added by `Engine.documents` (`engine.py:84-135`), which parses each file in a subprocess. On failure the attachment gets `"error": "Document unavailable or unreadable"` instead of `text`. The document budget is 12 s per message.
- Helpers in `arena_kit/play.py`: `latest`, `standing`, `live_threads` and `moves_left` (`round_limit` minus the buyer messages sent).
- `seconds_left` comes from the session's per-thread `seconds_left`, with 60 s as the default (`engine.py:149-151`). It resets to 60 after each reply (`engine.py:217`).

**`services`** (`worker.py:24-38`):
- `services.data` is a `DataPackage(cfg["data"])` (`arena_kit/data.py`):
  - `query(sql, params=(), limit=200)` accepts only SELECT or WITH and returns a list of dicts.
  - `lookup(ref)` returns a dict or None, from `facts.json` or a table row.
  - `ids(prefix)` returns a sorted list.
  - `document(ref)` returns text and raises `FileNotFoundError` if missing.
  - Also available: `tables()`, `facts`, `cases`.
- `services.cost(case, terms, standard=None, supplier=None)` calls `cost.total_cost`. It returns EUR, or `inf` if there is no price.
- `services.complete(messages)`:
  - It is **synchronous and blocking**. It writes a request on stdout and reads the answer with `sys.stdin.readline()`.
  - It returns `data["choices"][0]["message"]["content"]` (normally a string; `transport.py:174`).
  - **It is not thread-safe**, because of the shared stdin/stdout pipe. Calls from one worker must run one after another; `agent_process.py:40-50` also handles them one at a time.
  - The request body is only `model`, `messages` and `max_tokens`, or `reasoning_effort` plus `max_completion_tokens` (`transport.py:140-148`). There are no tools, `response_format` or temperature, so JSON has to be parsed from the text.

**Errors from `services.complete`:** every failure becomes `RuntimeError(&lt;exception type name&gt;)` (`agent_process.py:49-50` and `worker.py:32-33`).

| Cause | What the agent sees |
|---|---|
| No `[model]` configured, including `agents check` (`cli.py:222`, `transport.py:152-153`) | `RuntimeError("ValueError")` |
| Remote model without `--allow-model` (`transport.py:157-159`) | `RuntimeError("ValueError")` |
| Input over 128 KiB (`transport.py:160-161`) | `RuntimeError("ValueError")` |
| Budget exhausted | `RuntimeError("RuntimeError")` |
| HTTP error | `RuntimeError("HTTPStatusError")` |
| Timeout | `RuntimeError("ReadTimeout")` or similar |

If the agent does not catch this, `decide` fails and the case is closed by the safe fallback.

## 3. Timeouts and model budget

**Settings**
- `decision_seconds` defaults to 30 and must be greater than 0 and at most 30 (`config.py:60,81-82`).

**Effective budget for each `decide`** (`engine.py:261-265`):
```python
budget = min(decision_seconds, min(deadlines[s] for s in ready) - now - 5, cap - now - 90)
```
- If the budget is 0 or less, the engine raises `TimeoutError` without calling the agent (`engine.py:275-276`).

**On timeout or error**
- `asyncio.wait_for` cancels the call and the worker process is killed (`agent_process.py:56-60`).
- The engine logs a `fallback` event (phase `decide`) and sets `force_close=True` (`engine.py:283-286`).
- It then plays `close_action` (`validation.py:40-51`): accept the cheapest acceptable standing offer, or walk away.
- **The case ends. There is no second decide.**
- The same happens if the output is invalid (`validate`, `validation.py:54-126`) or names a busy supplier (`engine.py:278-280`).

**Within the budget**
- Model calls inside one `decide` run one after another.
- Each model HTTP call has its own `timeout` (default 20 s, maximum 25 s; `config.py:123-124`).
- Model calls share one `Models` instance across the whole run (`engine.py:31`), limited by `model.parallel` (default **2**; `transport.py:132`). With 10 cases running, calls queue behind that semaphore. Raise `parallel` (maximum 10).
- If a model call is cancelled mid-flight, it is still counted, with status `unknown` (`transport.py:175-177`).

**`max_calls`**
- Required when `[model]` is set (`config.py:118-120`).
- `Journal.reserve_model` counts every row in `model_calls`, inside a `BEGIN IMMEDIATE` transaction (`state.py:119-127`).
- The count covers the whole run, persists across restarts and resume, and includes failed and unknown calls. There is no retry.
- Over the limit you get `RuntimeError("Model call budget exhausted")`.
- Size it as cases × decisions × sub-steps (plus reflections).

**Other limits**
- The worker-to-engine pipe has a 256 KiB line limit (`agent_process.py:25`). Both the `decide` reply and the `state` must fit, or the call fails and the fallback closes the case. Keep `state` small.
- Outgoing messages are limited to 64 KiB (`validation.py:77`).

## 4. Filesystem, sandbox and dependencies

- **Working directory:** `ROOT` = `starter-kit/` (`agent_process.py:20`, `config.py:13`).
- **Environment:** only `PATH`, `HOME`, `LANG`, `TMPDIR` and `SYSTEMROOT` are passed (`agent_process.py:15`). There is no `LLM_API_KEY`, `ARENA_*` or `PYTHONPATH`.
- **No OS sandbox:** files and network are unrestricted. HARNESS.md says "Plugins are trusted Python code, not an OS security sandbox; use `services.complete` for all model calls".
- **stdout is reserved** for the protocol. The worker redirects stdout to stderr (`worker.py:44`), and the engine sends the worker's stderr to `DEVNULL` (`agent_process.py:24`). All `print` and logging output is lost, so log to a file.
- **Where memory can safely go:**
  - `authorize` for the final requires a clean checkout (`config.py:145`).
  - `verify_source` runs before **every automatic engine restart** (`cli.py:80`) and fails if the final is dirty (`cli.py:38-39`). Untracked memory files in the repo would therefore block crash recovery.
  - `verify_source` also hashes `arena_kit/`, the data dir and the agent file (`cli.py:31-37`), so never write there.
  - Use a gitignored directory. The repo-root `.gitignore` already lists `.runs/`; you could add something like `.memory/`.
  - The agent does not receive the run ID or run dir. Build paths from `Path(__file__)` or pass them through `[parameters]`, which arrive in `prepare`; store them in `state`.
- **Dependencies:**
  - The worker runs with `sys.executable`, the venv Python, so anything installed in `.venv` can be imported.
  - Current `pyproject.toml` dependencies: `httpx`, `openpyxl`, `pypdf`. Extras: `anthropic`, `mcp`, `sim`.
  - The docs use `uv sync --frozen`. To add langgraph or another package, add it to `pyproject.toml`, run `uv lock`, and commit `uv.lock`.
  - LangChain LLM clients will not work as they are, because the worker has no API keys. Wrap `services.complete` instead.
  - Heavy imports count against the `prepare` timeout (≤30 s).

## 1. Problems found, checked against the code

### Will break or lose a case

**B1. Two serial LLM calls don't fit the budget, and a call can't be cut short.**
- The engine kills the worker when `budget = min(decision_seconds≤30, min_ready_deadline−now−5, cap−now−90)` runs out (`engine.py:261-265`, `agent_process.py:57-60`). It then force-closes the case through `close_action` (`engine.py:283-286`).
- `services.complete` is a blocking `readline` on stdin (`worker.py:28-34`). You can't abandon it. A late reply would land on stdin and corrupt the next request.
- Each call can take up to `[model].timeout` (≤25 s, default 20; `config.py:123`, `transport.py:134`). It can also queue first behind `Semaphore(parallel)` (default 2; `transport.py:132,162`). The plugin can't see that queue.
- At a wave start, up to 10 cases make their first decide at the same moment. With `parallel=2`, the 9th and 10th wait 4 or more call-lengths, the worker gets killed, and the harness picks the close.
- **Fix:**
  - Make one LLM call per decide the default.
  - Set `[model] parallel = 10` and `timeout = 12–15`.
  - Only start a call if the remaining time is at least the call timeout plus a margin (section 3).
  - Two calls are only possible when `timeout ≤ 12`: 2×13 + 2 = 28 s, just under the 30 s cap.

**B2. A missing optional extra means no case gets played.**
- The plugin module is loaded when the worker starts (`worker.py:15-21,46`). If `import langgraph` fails, prepare fails, `engine.py:178-183` records "Agent preparation failed" and the case is never played. In the final that scores the alternative, or 0 if there is none.
- The documented install (`HARNESS.md:9`) is `--extra sim --group dev`, which won't install a `learner` extra.
- **Fix:**
  - In `agents/learner.py`, import `agents._learner` lazily inside `prepare` and `decide`, wrapped in try/except, and fall back to a sequential runner that uses the same node functions.
  - Put `langgraph` in the base `dependencies`, or document `--extra learner` everywhere and commit the new `uv.lock`. `--frozen` won't resolve an extra that isn't in the lock.

**B3. NaN or inf in state or actions crashes the reply.**
- `encode()` uses `allow_nan=False` (`state.py:14`), and the worker encodes every reply (`worker.py:55-58`).
- `total_cost` returns `math.inf` for a sheet with no price (`cost.py:165-166`). Storing that C in state makes `decide` return an error, which triggers a force-close.
- **Fix:** run `sanitize()` (inf/nan → None) over state and actions before returning.

**B4. The reply line is capped at 256 KiB.**
- The engine reads worker stdout with `limit=256*1024` (`agent_process.py:25`). The whole `{"result": {"actions", "state"}}` line counts, including the state.
- The model request line is separately capped at 128 KiB of encoded messages (`transport.py:160-161`). Above that it raises `ValueError`, which reaches the plugin as `RuntimeError("ValueError")` — the same signal as "model disabled".
- **Fix:** keep the dossier and claim catalog in the process, not in state (the worker lives for the whole case: `engine.py:166`, `agent_process.py:36-38`). Keep JSON state at 48 KiB or less (hard cap 128 KiB) and the prompt at 60 KiB or less.

**B5. In an RFQ, an accept sent while another thread is in flight is replaced by the harness's own choice.**
- `engine.py:289-292`: a closing action with `pending` non-empty sets `force_close`. After the pending replies settle, `close_action` picks the lowest-C acceptable standing offer, computed without the relationship term (`validation.py:40-51`).
- **Rule:** accept only when `set(live_threads) − set(ready)` is empty. Otherwise either accept knowing the harness picks the lowest C (fine when that is also your choice, which isn't always true in stabilise or secure_supply cases), or send a hold message.

**B6. A thread can't wait, so every decide must act on every ready supplier.**
- An omitted ready supplier stays ready, and `decide` is called again straight away (`engine.py:247,257-260,336`).
- `validate` rejects an empty action list (`validation.py:55-56`), which triggers a fallback.
- Messaging a thread with `moves_left ≤ 0` force-closes the case (`engine.py:330-334`).
- So a ready thread with no moves left forces a close at that decide. The only way to "wait" is a hold message: a question with no term sheet ("the quote stands", `api.md:205`). Each hold costs a round.
- Pace RFQ threads evenly and treat the round limit as a shared budget.

## 2. Refined design: build the offer menu first, then one LLM call

Have the code build the menu of valid offers **before** the LLM call. The LLM picks from the menu and writes the e-mail with placeholders. That needs only one call and keeps all figures out of the model's hands.

```
observe(det) → route(det) ─close→ emit
                       └─continue→ menu(det: candidates + claim catalog) → [negotiate LLM | det_policy] → finalize(det: substitute, lint, validate) → emit
```

- **Menu.** For each lever combination in `itertools.product(term_options…)` (at most about 150), solve the price so that `supplier_value(...)` hits a target. That gives packages of equal value to the supplier. Keep the 6–9 cheapest for us (by C), across 2–3 concession levels.
  - Supplier model: `{standard: stated_open ∪ standard, interest_rate: 0.15 if cash_short else 0.07, full_cost: from the cost-breakdown XLSX, should_cost, or none}`.
  - For stabilise and secure_supply goals, minimise `total_cost(..., supplier=est)`; the relationship term makes very low prices more expensive.
- **The deterministic fallback uses the same menu.** It follows a slow-concession schedule: target `C_k = C_asp + (C_stand − C_asp)·(k/K)^3` with `K = min(moves_left, rounds that fit before the wave cap)`.
- **Strategist refresh.** Refresh the plan only on events: round 0, a status change, a contradicted claim, a new attachment, or a supplier move above 1.5%. Otherwise one call updates the plan and writes the e-mails. Store the plan in state.

## 3. Time-budget policy for `decide`

```
t0 = monotonic() at entry
E  = P.decision_seconds (mirror of TOML; 30)
S  = min(obs.seconds_left[s] for s in ready)
W  = obs.wave_seconds_left            # None outside the final
B  = min(E, S - 5, (W - 90) if W is not None else inf)      # same formula as engine.py:261-265
DEADLINE = t0 + B - 2.0               # return margin: validate + encode + pipe
T  = P.model_timeout + 1.0            # mirror of [model].timeout (use 14 → T=15)
R(now) = DEADLINE - now
```

| Condition (checked after observe + menu, which must take ≤ 0.6 s) | Mode |
|---|---|
| `B ≤ 4` or menu not built in time | reflex: deterministic, cached data only |
| `P.llm` is false, or 2 or more consecutive LLM failures this case, or budget exhausted | deterministic |
| `R ≥ 2T + 1` and `T ≤ 13` and refresh due and every live thread is in `ready` | two calls (strategist, then writer) |
| `R ≥ T + 1` | one merged call |
| otherwise | deterministic |

- Never retry a model call. On a parse failure, use the deterministic path with the same menu.
- After the LLM returns, if `R &lt; 0.8`, skip lint repairs and use the template body.
- **Wave pre-close.** Let `L` = the largest supplier reply latency seen so far (state `sent_at`; default 45 s) and `D` = 15 s. If `W − 90 &lt; L + D + 10`, this is the last round:
  - Accept your own best acceptable offer if nothing is pending.
  - Otherwise send only moves that don't push a final_offer supplier; the harness's cap-time `close_action` is then acceptable.
- **Recommended TOML:** `decision_seconds=30`; `[model] parallel=10, timeout=14`; for the final, `max_calls≈1500` (5 waves × 6 cases × about 15 decides × 1–2 calls, plus headroom); `max_output_tokens=2500` for a non-reasoning model or 6000 for a reasoning model at low effort.
- **Prepare budget:** 3 s or less. If the dossier isn't finished at 2.5 s, return partial state with `degraded=true`. prepare must never raise (`engine.py:178-183`).

## 4. Claim catalog rules (`api.md:238-260`)

General rules:
- **IDs.** Allowed IDs are `facts.json` ∪ `release-sunday/facts.json` (merged by `DataPackage`) ∪ `case["facts"]` ∪ `offer:` IDs from this session.
- **Figures.** Every figure is computed from the fact values and written with one decimal for % and two decimals for EUR, so it is always inside tolerance (±0.5 pp for %, ±0.5% relative otherwise).
- **Sentence shape.** One argument per sentence, and only one figure in it. Keep dates inside the IDs only.
- **Limits.** At most 3 claims per message.
- **Duplicates.** Compute used IDs from `threads` (your past `refs` plus ID tokens in your bodies), so it survives a resume. Each ID is used once per case; a rival's `quote:` or `offer:` is used once per supplier.

| Kind | Build rule | Figure | Use when |
|---|---|---|---|
| `idx` pair | Series is in `cost_drivers` for the case part, in `index_paths`, or named in the trigger letter. `later` = the series' latest month (most end 2026-08 or 2026-09; LCI-C ends 2026-06; it must be ≥ 2025-10). `earlier` = `later` − 12 months exactly, and both must exist. | `(v_l/v_e − 1)·100`, 1 decimal, % | The change is below the supplier's asked % or its weighted share |
| `quote` | Only IDs in `case.refs` or `buyer.alternative.ref`; `fact.part` must be in `case.parts`. | `unit_price` per `price_unit` (say "per 100" if needed), EUR | It's cheaper than the standing offer |
| rival `offer:` | RFQ only: another supplier's current standing sheet, same part. | Its `unit_price`, EUR | Rival price below this supplier's; this reveals the price, so do it deliberately |
| `sc` | One row, `sup` == thread supplier, latest quarter (`2026Q3`). Wording "on-time delivery" → `otd_pct` (not `otd_confirmed_pct`); wording "ppm/quality" → `ppm`. | % or ppm | Weak OTD or PPM, to argue for a ppm or chargeback lever or a lower price |
| `qn` | 1–3 rows, same supplier and part. | mean `ppm`, rounded to an integer | Quality cases |
| `po` | 2–8 rows, same part and supplier, all at the **same** `unit_price` (latest ones). | That exact price, or no figure | History is below the offer |
| `fc` | `fc:&lt;part&gt;@YYYY-MM` for the case part, latest month. | `change_pct`, % | Volume up (don't cite a fall) |

## 7. Routing and closing rules (deterministic, before the LLM)

- **Accept** only if all of these hold:
  - `validation.acceptable(case, threads[s])` is true.
  - `pending` is empty.
  - Status is `agreed`, or status is `final_offer` and `C ≤` your reservation (alternative, or estimated C_best + slack).
  - No other live thread has a lower `C_est`.
- **RFQ with `agreed` while a rival is pending:** accept anyway only if this offer is also `close_action`'s argmin; otherwise send a hold message.
- **Walk away** only if the alternative is not `none` and every live acceptable C is above `C_alt`, and either no moves are left or everyone is at `final_offer`. If the alternative is `none`, never walk; accept the best acceptable offer.
- **`final_offer`:** push at most once, and only with a package of equal value to the supplier (no pure price push), and never inside the wave pre-close window.
- **A ready thread with `moves_left == 0`:** close now (B6).
